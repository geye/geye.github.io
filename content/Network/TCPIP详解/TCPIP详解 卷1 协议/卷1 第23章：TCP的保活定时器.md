# 第23章 TCP的保活定时器

## 23.1 引言

保活定时器检测空闲连接的另一端是否崩溃。

### 争议
1. 临时故障可能导致连接关闭
2. 耗费带宽
3. 按分组计费时增加费用

## 23.2 描述

### 四种情况
1. **正常**：客户响应→定时器复位
2. **崩溃**：无响应→10次探查（间隔75秒）→关闭
3. **崩溃后重启**：响应RST→关闭
4. **不可达**：无响应→软差错

### 默认配置
- 空闲2小时后发送探查
- 75秒间隔
- 10次探查后放弃

## 23.3 保活举例

### 另一端崩溃
read error: Connection timed out

text
- 2小时空闲
- 10次探查（75秒间隔）

### 另一端崩溃并重新启动
read error: Connection reset by peer

text
- RST响应探查

### 另一端不可达
read error: No route to host

text
- ICMP差错变为软差错

## 23.4 小结

保活定时器检测空闲连接的状态。四种情况产生不同的响应。
